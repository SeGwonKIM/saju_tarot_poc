# 잠금 시험셋 만들기 — 문제 내실 분께

> 읽는 데 5분, 만드는 데 40분쯤 걸립니다.
> **이 프로젝트를 만든 사람이 아닌 분**이 만들어야 의미가 있습니다.

---

## 왜 부탁드리나

프로그램이 상담 녹취에서 **이름·성별·생년월일·시각·고민**을 뽑아냅니다.
"몇 %나 맞히나"를 재고 있는데, 지금까지 쓴 문제는 전부 **만든 사람이 직접 낸 것**입니다.

시험 문제를 낸 사람이 시험을 보면 점수가 높게 나옵니다. 답을 아니까요.
그래서 **프로그램이 한 번도 본 적 없는 문제**가 필요합니다.

**틀리게 만드는 것이 목적이 아닙니다.** 실제 상담에서 나올 법한 말을 쓰시면 됩니다.

---

## 만드는 법

### 1. 상담 대화를 15건 씁니다

`상담_101.txt` 부터 `상담_115.txt` 까지, 이런 모양으로 적어 주세요.

```
상담자: 네 안녕하세요. 사주 문의 주셨죠.
의뢰인: 네 안녕하세요. 제 사주 좀 보려고요.
상담자: 성함이 어떻게 되실까요?
의뢰인: ...
```

- 줄마다 `상담자:` 또는 `의뢰인:` 로 시작합니다.
- **실제 사람 이름·생년월일을 쓰지 마세요.** 전부 지어내신 것으로 합니다.
- 길이는 10~20줄이면 충분합니다.

### 2. 이런 것들이 섞이게 해 주세요

프로그램이 어려워하는 자리가 있습니다. **15건 안에 아래가 골고루 들어가면** 좋습니다.

| | 섞어 주실 것 | 예 |
|---|---|---|
| 1 | **음력** 으로 말하는 사람 | "음력 칠월 스무날이요" |
| 2 | **윤달** 을 말하는 사람 | "윤달이라고 하셨어요" |
| 3 | 날짜를 **한글**로 말하는 사람 | "천구백칠십이년 십일월 삼일" |
| 4 | 말하다 **고치는** 사람 | "사월... 아니 오월이네요" |
| 5 | 시간을 **모르는** 사람 | "그건 어머니도 기억을 못 하세요" |
| 6 | 시간을 **애매하게** 말하는 사람 | "아침 여덟시쯤인데 정확하진 않아요" |
| 7 | **밤 11시~새벽 1시** 사이에 태어난 사람 | "밤 열한시 사십분이요" |
| 8 | **성별을 말하지 않는** 사람 | (그냥 안 물어보시면 됩니다) |
| 9 | **태어난 곳을 말하지 않는** 사람 | 〃 |
| 10 | **본인이 아니라 가족** 사주를 보러 온 사람 | "어머니 사주를 좀…" |

**⚠ 8·9번이 특히 중요합니다.** 일부러 비워 두신 자리가 **최소 5개**는 있어야 합니다.
프로그램이 모르는 걸 "모른다"고 하는지, 아니면 **지어내는지**를 보는 자리입니다.

### 3. 정답을 적습니다

`정답키_시험셋.json` 에 이렇게 적어 주세요. 대화에 **안 나온 것은 `null`** 입니다.

```json
{
  "101": {
    "name": "김하늘",
    "gender": "female",
    "birth_date": "1995-03-12",
    "calendar_type": "solar",
    "is_leap": false,
    "birth_time": "15:20",
    "birth_place": "서울",
    "question": "이직 시기",
    "question_keywords": ["이직", "직장", "옮길"]
  }
}
```

| 칸 | 어떻게 적나 |
|---|---|
| `name` | 대화에 나온 이름. **사주를 보는 사람** 이름입니다 (물어본 사람이 아니라) |
| `gender` | `male` / `female` / 안 나왔으면 `null` |
| `birth_date` | `YYYY-MM-DD`. **음력이면 음력 날짜 그대로** 적습니다 (양력으로 바꾸지 마세요) |
| `calendar_type` | `solar`(양력) / `lunar`(음력) |
| `is_leap` | 윤달이면 `true`, 평달이면 `false`, 음력인데 안 물어봤으면 `null` |
| `birth_time` | `HH:MM` (24시간). 모르면 `null` |
| `birth_place` | 시 단위. 안 나왔으면 `null` |
| `question` | 고민을 한 마디로 |
| `question_keywords` | **인정할 낱말 2~4개.** 표현이 달라도 이 중 하나가 들어가면 맞은 것으로 칩니다 |

## 만드신 뒤 — 지켜 주실 두 가지

### ① 넘겨주실 때까지 내용을 보여주지 마세요

만든 사람이 문제를 미리 보면 **그 순간 시험셋이 아니게 됩니다.**

### ② 채점은 **한 번만** 합니다

두 번째부터는 "답을 보고 고칠 수 있는" 상태가 되므로 시험셋이 아닙니다.

---

## 넘겨받는 쪽이 할 일

```bash
# ① 문제를 받기 전에 — 채점기·프롬프트를 봉인
python -m verify.seal 봉인

# ② 문제를 받은 뒤 — 봉인이 그대로인지 확인
python -m verify.seal 확인

# ③ 확인이 통과했을 때만 채점 (딱 한 번)
python -m verify.s1_extract --시험셋 --llm --env=경로/.env
```

**②에서 하나라도 바뀌었으면 그 회차는 무효입니다.** 문제를 보고 나서 프로그램을
고쳤다는 뜻이기 때문입니다.

---

## 왜 15건인가

표본이 3건이면 **한 건만 어긋나도 33%p** 가 움직입니다. 그 숫자로는 아무 말도 못 합니다.
15건이면 한 건이 **6.7%p** 라 그나마 읽을 만해집니다.

더 많으면 좋지만, 만드시는 분 시간이 더 중요합니다. **15건이면 충분합니다.**
