## S4 — 재현성 (3분할)

**실행** `python -m verify.s4_repro --env=<경로>/.env --횟수=4` · **출력** `out/s4_결과.txt`

### 단일 지표를 버린 이유 (검토의견 §4-3)

예전 S4 는 "같은 입력에 같은 답이 나오는가" 하나였습니다. 두 가지가 잘못됐습니다.

1. **캐시만 넣으면 100%** 가 됩니다. 두 번째 실행은 모델을 부르지 않으므로 "같은 출력"이 아니라
   "같은 파일"을 재는 것이 됩니다. 지표가 이렇게 쉽게 속으면 지표가 아닙니다.
2. **무엇이 흔들리는지 알려주지 않습니다.** 파이프라인에는 코드 구간과 LLM 구간이 섞여 있는데,
   문장이 달라지는 것은 정상이고 원국이 달라지는 것은 사고입니다. 한 숫자로 묶으면 구별이 안 됩니다.

| | 대상 | 목표 | 현재 |
|---|---|---|---|
| **S4a** | ③④⑤⑥ 만세력·보정·사실 블록 (**코드**) | **100%** — 1%라도 흔들리면 버그 | 미측정 |
| **S4b** | ② 항목 추출 (**LLM**) | **100%에 가깝게** — 값이 틀리면 조용히 틀린 리포트가 나감 | **미달** |
| **S4c** | ⑦ 리포트 문장 (**LLM**) | 목표 없음 — 분포만 본다 | 미측정 |

### S4b 측정값

| 방법 | 매번 동일 | 흔들린 항목 |
|---|---|---|
| 규칙 기반 | **100.0%** (21/21) | 0개 |
| LLM | 95.2% (20/21) | 1개 |

**분모 정의** (검토의견 M-4): 표본 3건(002·005·007) × 필드 7개 = 21개. 각 표본을 4회 실행해
**모든 회차에서 값이 같은 필드**를 셌습니다. 비교는 **완전일치**입니다.
**조건**: `gpt-4o-mini-2024-07-18` · temperature 0 · seed 20260922 · 프롬프트 해시는 `run.json` 에 기록.

흔들린 자리는 하나였습니다.

```
007  birth_date:  1947-02-17 (3회)  ·  1947-03-08 (1회)
```

**`temperature=0` 인데도 갈렸고, 두 값이 다 틀렸습니다** (정답 `1947-02-08`).
프롬프트를 고친 뒤 재측정하면 `1947-02-18` 이 나옵니다 — **여전히 틀립니다.**

### 이게 뜻하는 것

> **자동 통과는 안 됩니다.** 추출 결과를 사람이 확인하는 화면이 반드시 있어야 합니다.

특히 음력·윤달이 위험합니다. `is_leap` 하나가 어긋나면 원국 여덟 글자가 통째로 바뀌는데,

처음 쓴 계좌번호 무늬 `\d{2,6}-\d{2,6}-\d{2,7}` 은 **`1990-12-31` 도 삼킵니다.**

| **전부 내가 쓴 가상 대화다** | 실제 말버릇·사투리·말 겹침·잡음이 없음. STT 를 거치면 훨씬 지저분함 |
| **숫자 대조 검사는 자화자찬이다** | 오답 3건을 **이미 알고서** 만든 검사라 잡는 게 당연. 새 숨김 문제로 재측정 필요 |
| **숫자 대조 파서가 거칠다** | `십일월` 에서 10 이, `오일장` 에서 5 가 날짜로 새어 들어옴. 너그러운 쪽이라 정답을 막진 않지만 탐지력이 떨어짐 |
| **S3 분모가 가정이다** | 65분은 재 본 적 없음 |
| **① 받아쓰기를 한 번도 안 돌렸다** | 전부 텍스트 입력. Whisper 경로는 코드만 있고 **미검증** |
| **공개 문제로 기준선을 튜닝했다** | 그래서 공개 25/25 는 실력이 아님. 이미 본문에 적었으나 다시 강조 |
