## 0. 먼저 — 어디에 AI를 쓰고 어디에 안 쓰는가

이 PoC 의 설계 원칙 한 줄이 모델 선정을 거의 다 결정했습니다.

> **계산은 코드가, 문장은 AI가.**

| 단계 | 누가 | 왜 |
|---|---|---|
| ① 받아쓰기 | **AI (STT)** | 말소리 → 글자는 규칙으로 못 함 |
| ② 항목 추출 | **AI (LLM)** | 사람 말투가 무한히 다양함 |
| ③ 음양력 변환 | 코드 | **답이 정해져 있음.** AI 에 맡기면 지어냄 |
| ④ 진태양시·서머타임 | 코드 | 〃 |
| ⑤ 원국·세운 | 코드 | 〃 |
| ⑥ 사실 블록 | 코드 | 〃 |
| ⑦ 리포트 문장 | **AI (LLM)** | 정답이 없는 글쓰기 |

③~⑥을 AI 에 맡기지 않은 것이 **가장 중요한 선택**이었고, 실측으로 옳았음이 확인됐습니다.
→ 3절 참조.

## 1. ① 받아쓰기 — `faster-whisper` (large-v3-turbo)

### 고른 것

| | |
|---|---|
| 모델 | `mobiuslabsgmbh/faster-whisper-large-v3-turbo` |
| 실행 | `faster-whisper` (CTranslate2 백엔드), CPU/int8, 16스레드 |
| 도구 | `C:/AI-Agent/whisper_mcp/transcribe.py` — **이미 만들어 둔 것을 재사용** |

### 후보와 비교

| 후보 | 장점 | 왜 안 골랐나 |
|---|---|---|
| **faster-whisper turbo** ✅ | 로컬 실행 → **음성이 밖으로 안 나감**. 무료. 한국어 양호 | — |
| `openai-whisper` (원본) | 같은 모델 계열 | 같은 정확도에 **더 느리고 메모리를 더 씀**. CTranslate2 쪽이 int8 양자화로 CPU 에서 유리 |
| OpenAI Whisper **API** | 서버가 대신 돌려 빠름 | **음성 원본이 국외로 나감.** 상담 녹취는 실명·생년월일이 담긴 민감 자료다 (§6-1) |
| Google STT / Naver Clova | 한국어 품질 좋음, 화자 분리 지원 | 유료 + 국외/외부 전송. PoC 단계에서 비용·계약이 생김 |
| `small` / `medium` 모델 | 훨씬 빠름 | 숫자와 고유명사에서 불리. **이 도메인은 숫자 하나가 원국을 바꾼다** |

### 결정적인 이유

**개인정보입니다.** 상담 녹취에는 음성 원본 + 실명 + 생년월일시가 들어 있습니다.
API 를 쓰면 그 음성이 그대로 국외로 나갑니다. 로컬에서 도는 모델이면 **안 나갑니다.**

텍스트(②⑦)는 결국 LLM API 로 나가지만, **음성 원본까지 내보낼 이유는 없습니다.**
줄일 수 있는 것부터 줄이는 것이 맞습니다.

### 실제로 돌린 결과 (2026-09-23)

| | |
|---|---|
| 표본 | 합성 음성 2건 (61.6초, 45.7초) |
| 글자 유사도 | **88.3% / 97.4%** |
| 추출 점수 | 텍스트 13/14 → **음성 13/14** (낙폭 0%p) |
| 속도 | **실시간의 1.1~1.6배** (CPU) |

⚠ **합성 음성이므로 이 점수는 상한선입니다.** 실제 통화에는 잡음·말 겹침·사투리가 있습니다.

### 여기서 나온 가장 큰 발견

**속도가 문제입니다.** 실시간의 1.1~1.6배면, 10~30분 상담의 받아쓰기에만 **11~48분**이 걸립니다.
기존 S3 은 이 시간이 **통째로 빠진 채** 계산돼 있었습니다.

| 해결 방향 | 비고 |
|---|---|
| GPU 사용 | 가장 확실. Colab 무료 T4 로도 수 배 빨라짐 |
| 더 작은 모델 | 숫자 정확도가 떨어져 이 도메인에는 위험 |
| 상담 중 실시간 처리 | 통화가 끝나면 받아쓰기도 끝나 있음 — **설계로 푸는 방법** |

## 2. ②⑦ 항목 추출·리포트 문장 — `gpt-4o-mini-2024-07-18`

### 고른 것

| | |
|---|---|
| 모델 | `gpt-4o-mini-2024-07-18` (**별칭이 아니라 날짜 고정판**) |
| 설정 | ② temperature 0 · seed 20260922 · `json_schema` strict / ⑦ temperature 0.4 |

### 왜 별칭이 아니라 날짜 고정판인가

`gpt-4o-mini` 는 **별칭**이라 실체가 조용히 바뀝니다. 그러면 지난달 측정값과 이번 달
측정값을 비교할 수 없게 됩니다. 재현성을 재는 프로젝트에서 이건 치명적입니다.
그래서 날짜를 못 박고 `system_fingerprint` 를 `run.json` 에 기록합니다.

### 후보와 비교

| 후보 | 왜 안 골랐나 |
|---|---|
| **gpt-4o-mini** ✅ | 구조화 출력(json_schema strict) 지원 · 저렴(건당 약 1원) · 한국어 양호 |
| 더 큰 모델 (gpt-4o 급) | 남은 오답이 **음력 날짜 3건**뿐인데, 그건 모델을 키워서 풀 문제가 아니라 **되묻기로 풀 문제**였다 (4절). 비용만 수 배 |
| 로컬 LLM (Llama·Qwen 등) | 개인정보 면에서는 최선. 다만 **구조화 출력 강제**와 한국어 명리 문맥에서 PoC 기간 내 안정화가 어렵다. **상용 전환 시 재검토 대상** |
| 규칙 기반(정규식)만 | **실제로 만들어서 나란히 쟀다.** 아래 참조 |

### 기준선을 반드시 옆에 두었습니다

LLM 만 재면 "좋다/나쁘다"를 말할 수 없습니다. 그래서 정규식만 쓰는 추출기를
**같은 자로** 쟀습니다.

| | 학습셋 5건 | 검증셋1 3건 | 검증셋2 3건 |
|---|---|---|---|
| 규칙 기반 | 34/35 (97%) | 16/21 (76%) | 16/21 (76%) |
| **LLM** | 33/35 (94%) | **20/21 (95%)** | **20/21 (95%)** |

**학습셋만 보면 규칙 기반이 이깁니다.** 그런데 그 97% 는 제가 정규식을 고쳐 가며 만든
점수라 무효입니다. **처음 보는 문제에서는 규칙 기반이 76% 로 무너지고 LLM 은 95% 를 지킵니다.**

> 이게 LLM 을 쓰는 이유입니다. "말투가 바뀌어도 버틴다."
> 기준선이 이겼다면 LLM 을 안 쓰는 것이 맞았습니다.

## 3. ③~⑥ 계산 — AI 를 **쓰지 않았습니다**

| 쓴 것 | 하는 일 |
|---|---|
| `lunar-python` | 간지·절기 (원국 8글자) |
| `korean-lunar-calendar` | 음↔양력 변환·윤달 |
| 직접 짠 코드 | 진태양시·서머타임·표준자오선 보정 |

### 이 선택이 옳았다는 실측 증거

LLM 은 **시키지 않았는데도 달력 계산을 시도했고, 세 번 다 틀렸습니다.**

| 표본 | 말한 것 | LLM 이 낸 값 | 정답 |
|---|---|---|---|
| 002 | 음력 **7월** 20일 | `1988-08-20` | `1988-07-20` |
| 007 | 음력 **윤2월 초여드레** | `1947-02-18` | `1947-02-08` |
| 010 | 음력 **윤유월 초닷새** | `1960-07-05` | `1960-06-05` |

002 의 `08-20` 은 **말한 날짜도 아니고 그 음력의 올바른 변환값(`08-31`)도 아닙니다.**
007 은 `is_leap: true` 를 맞게 넣고도 월을 한 칸 올렸습니다 — 윤달을 두 번 센 것입니다.

반면 코드 구간은 **8표본 × 20회 전부 동일**했습니다 (S4a 100%).

> **이름·성별·시각·출생지·고민은 11건 전부 맞혔습니다. 틀린 자리가 오직 달력 계산뿐입니다.**
> "계산은 코드가, 문장은 AI가" 가 실측으로 증명된 셈입니다.

## 4. 모델을 키우는 대신 고른 것 — 되묻기

남은 오답 3건이 전부 음력 날짜였습니다. 선택지는 둘이었습니다.

| | 방법 | 판단 |
|---|---|---|
| A | 더 큰 모델을 쓴다 | 비용 수 배. **없어진다는 보장도 없음** |
| B | **틀릴 수 있는 자리를 골라 사람에게 되묻는다** | ✅ |

B 를 골랐습니다. 오프라인 상담에서 이미 하는 일입니다 — "생년월일 다시 불러 드릴게요".

**측정 결과** (표본 11건 전수)

| | |
|---|---|
| 정답을 넣었을 때 잘못 경고 | **0/11** |
| 하루 어긋난 값을 넣었을 때 탐지 | **11/11** |

```
⚠ 뽑아낸 '17일' 이 대화에 안 나옵니다 (대화에 나온 일: [8])
  "송복희 님, 음력 윤달 1947년 2월 17일, 오전 10시, 전주 출생, 여성 — 맞으실까요?"
```

⚠ 이건 **정확도가 좋아진 게 아닙니다.** 모델은 여전히 `02-17` 을 냅니다.
틀린 것을 **틀렸다고 알려 주게** 됐을 뿐입니다.

## 5. 모듈에서 배웠지만 **안 쓴** 모델과 이유

| 모델 | 왜 이 도메인에 안 맞나 |
|---|---|
| **YOLO** (객체 탐지) | 상담에 이미지가 없습니다. 굳이 쓴다면 손글씨 사주 용지 촬영본 인식인데, PoC 범위 밖이고 OCR 이 더 맞습니다 |
| **SAM** (세그멘테이션) | 같은 이유 |
| **Diffusion** (이미지 생성) | 리포트에 삽화를 넣을 수 있으나 **상담 품질과 무관**합니다. 오히려 "예쁜 그림으로 신뢰를 산다"는 방향이라 이 서비스에는 위험합니다 |
| **음성 생성(TTS)** | 리포트를 읽어 주는 용도는 가능. 다만 **검수 전 초안을 음성으로 내보내는 건 위험**합니다. 상용 단계 검토 대상 |

단 **TTS 는 시험 도구로 썼습니다** — 상담문을 음성으로 만들어 STT 경로를 검증했습니다
(`samples/make_audio.ps1`). 제품 기능이 아니라 **표본을 만드는 데** 썼습니다.

## 6. 정리 — 한 줄씩

| 단계 | 고른 것 | 한 줄 이유 |
|---|---|---|
| ① | faster-whisper turbo (로컬) | **음성을 밖으로 안 보내려고** |
| ② | gpt-4o-mini (날짜 고정) | 처음 보는 말투에서 규칙 기반이 76%, LLM 이 95% |
| ③~⑥ | 코드 (lunar-python 등) | LLM 이 달력 계산을 세 번 다 틀렸음 |
| ⑦ | gpt-4o-mini | 정답이 없는 글쓰기 |
| — | **되묻기 게이트** | 모델을 키우는 것보다 싸고 확실함 |

### 아직 안 해 본 것

| | 왜 |
|---|---|
| 로컬 LLM | 개인정보 면에서 최선이나 PoC 기간에 안정화가 어려움. **상용 전환 시 1순위 재검토** |
| GPU / Colab | 받아쓰기 속도가 S3 의 병목. **다음 단계에서 반드시** |
| 화자 분리 | 상담자 말이 의뢰인 정보로 섞일 위험. 지금은 안 하고 있음 |
| 파인튜닝 | 표본 11건으로는 불가능. 데이터가 모인 뒤 |
